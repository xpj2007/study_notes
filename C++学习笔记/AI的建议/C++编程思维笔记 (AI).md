## 一、一句话记住区别

|          | C       | C++          |
| -------- | ------- | ------------ |
| 你脑子里想的是  | 先做啥，再做啥 | 这是什么东西，谁能动它  |
| 数据和函数    | 分开写     | 绑在一起         |
| 内存谁释放    | 靠你记着    | 让对象自己管       |
| 出错什么时候发现 | 运行时     | **尽量编译时就发现** |

**一句话**：写 C 时你想"这个函数干什么"；写 C++ 时你想"**这个数据归谁管**"。

## 二、最重要的一个思想：让对象自己管自己

这是 C++ 最值钱的东西，叫 **RAII**（名字不用记，理解意思就行）。

**意思就是**：对象出生时拿到资源，死亡时自动还回去。

看个例子。要读一个文件：

```c
// C 的写法：每个出口都得记得关
FILE *fp = fopen("a.txt", "r");
if (!fp) return -1;

if (读失败了) {
    return -2;          // 忘了 fclose！文件句柄泄漏了
}
if (检查失败) {
    return -3;          // 又忘了！
}

fclose(fp);
return 0;
```

```cpp
// C++ 的写法：不用管什么时候关
std::ifstream in("a.txt");
if (!in) return -1;

if (读失败了) return -2;   // 文件自动关
if (检查失败) return -3;   // 文件自动关
// 就算这里抛异常，文件也会自动关
```

**为什么好**：不管从哪里退出，都不用操心。**你不可能忘记一件不需要你做的事。**

### 记住这句话

> **谁申请，谁释放 —— 而且要让"释放"变成自动的。**

写 C++ 时养成习惯问自己两句：

1. 这个资源归谁管？
2. 它是自动释放的，还是要我手动释放？

## 三、另外五个小想法

### 想法 1：默认用"值"，别急着用指针

C 里习惯传指针省拷贝。C++ 里先想想：**我真的需要指针吗？**

```cpp
// 你要哪种？
void f(Widget w);            // 拷贝一份，改它不影响外面
void f(Widget &w);           // 引用，会改到外面
void f(const Widget &w);     // 引用但不能改（最常用）
void f(Widget *w);           // 指针，可能为空
```

**记不住就记这条**：不确定用哪个，就用 `const Widget &w`。
不拷贝（快），又不改（安全）。

**为什么少用指针好**：指针可能是空的、可能指向已经销毁的对象。用"值"和"引用"就没这些麻烦。

---

### 想法 2：别到处写 `if (类型 == 1)`

这是初学者最容易犯的设计问题。

```cpp
// ❌ 每加一个新东西，这些函数都要改
if (shape.type == 1)       area = 3.14 * r * r;
else if (shape.type == 2)  area = w * h;
else if (shape.type == 3)  area = 0.5 * a * b;
// 再加个"椭圆"？所有 if 都得改一遍
```

```cpp
// ✅ 让东西自己会算
class Shape {
    public:
        virtual double area() const = 0;
};
class Circle : public Shape {
    public:
        double area() const override { return 3.14 * m_R * m_R; }
};

// 用的时候完全不用管是什么形状
for (auto *s : shapes) {
    cout << s->area();          // 它自己知道怎么算
}
// 加"椭圆"？加一个新类就行，上面代码一行不用改
```

**判断标准**：只要你写了 `if (类型 == ...)`，就问一句：

> **这个判断能不能变成虚函数？**

### 想法 3：用类型把错误挡在外面

```cpp
// ❌ 用一个 int 表示状态，可以是任何值
int state = 99;          // 99 是什么意思？

// ✅ 只能是这几个值
enum class State { Idle, Running, Stopped };
State s = State::Idle;

// ❌ 年龄可以是 -5
worker.age = -5;

// ✅ 让类自己把关，创建出来就一定合法
void Worker::setAge(int age) {
    if (age < 1)   age = 1;
    if (age > 150) age = 150;
    m_Age = age;
}
```

**想法**：不要问"我该在哪几个地方检查"，要问"**怎么设计才能让它根本错不了**"。

---

### 想法 4：`const` 是承诺，不是装饰

```cpp
void showInfo() const;              // 我承诺：调用我不改对象
const string &getName() const;      // 承诺：只读，而且不拷贝
void f(const Worker &w);            // 承诺：不改传进来的对象
```

**习惯**：写函数时问自己一句 —— **"这个操作会改对象吗？"**

- 不会改 → 加 `const`
- 会改 → 不加

**好处**：加了 `const` 之后编译器会帮你检查。比如你在"保存"函数里不小心改了成员变量，编译直接报错提醒你 —— **它在帮你发现设计问题**。

---

### 想法 5：继承要少用，组合要多用

| | 什么时候用 | 例子 |
|---|---|---|
| **继承** | A **是一种** B | 圆是一种形状 ✅ |
| **组合** | A **有一个** B | 车有一个引擎 ✅ |

```cpp
// ❌ 错：引擎不是车的一种
class Car : public Engine { };

// ✅ 对：车"有一个"引擎
class Car {
    Engine m_engine;
};
```

**为什么少用继承**：基类一改，所有子类都可能出问题。组合更松、更安全。

**如果一定要继承，记住一条铁律**：

```cpp
class Base {
    public:
        virtual ~Base() = default;      // 基类析构必须加 virtual！
};
```

不加 `virtual`，用基类指针 `delete` 时，子类的析构函数不会被调用，资源就泄漏了。

## 四、怎么练（选 3 个做就行）

### 练法 1：关掉教程，重写一遍 ← 最有用

新建一个空文件夹，**不看任何参考**，凭记忆把你跟教程做过的项目重写一次。

卡住了不要马上查。先问自己：

- 这里需要什么数据？
- 谁拥有它？
- 我想要什么行为？

**为什么有用**：跟着视频敲的时候，"下一步写什么"是视频告诉你的。重写的时候，这个决定得你自己做 —— **这才是真本事**。

---

### 练法 2：故意把代码改坏

这个方法特别有效，因为你会亲眼看到原理。

| 改什么 | 会看到什么 | 学到什么 |
|---|---|---|
| 删掉基类的 `virtual ~` | 程序行为异常 / 内存泄漏 | 虚析构多重要 |
| 删掉函数的 `virtual` | 调用的永远不是子类版本 | 虚函数怎么工作 |
| 把所有 `delete` 注释掉 | 内存一直涨 | 泄漏长什么样 |
| 删掉 `if (数量 == 0) return;` | 空的时候崩溃 | 边界检查 |
| 把 `int` 改成 `char` 再 `cout` | 输出变乱码 | 类型宽度 |
| 把引用参数改成传值 | 修改没生效 | 值和引用的区别 |

**改坏 → 看懂 → 修好。自己修好的才算真懂。**

---

### 练法 3：用调试器，别用打印

```cpp
// ❌ 靠打印猜
cout << "到这里了" << endl;
cout << "num = " << num << endl;
```

改用调试器（CLion 里点行号左边设断点，然后调试运行）：

| 操作 | 作用 |
|---|---|
| 设断点 | 程序停在这里 |
| 单步跳过 | 执行下一行 |
| 单步进入 | 进到函数里面看 |
| 看变量 | 看所有变量的值 |
| 看调用栈 | 我是被谁调用的 |

**强烈推荐**：单步进入一个虚函数调用，看它怎么"自动"选到正确的实现。**看过一次，多态就不是抽象概念了。**

---

### 练法 4：写代码前先写三行设计

```
类名：FileHandle
管什么：一个文件
拥有什么：文件指针（我负责关）
不管什么：文件内容怎么解析（那是调用方的事）
```

**说不清职责的类，就是没设计好的类。**

## 六、看到这些就要警惕

| 坏味道 | 什么意思 |
|---|---|
| 类里全是 get/set | 这只是个数据袋子，没有行为 |
| 函数名和做的事不符 | 比如 `getName()` 却会打印 |
| 到处 `if (类型 == 1)` | 该用虚函数了 |
| 多处重复的代码 | 该提到基类或抽成函数 |
| 不知道谁该 `delete` | 所有权不清楚 |
| `#define` 定义常量 | 改用 `const` 或 `constexpr` |
| 头文件里 `using namespace std;` | 会污染所有包含它的文件 |
| 构造函数里读用户输入 | 这个类没法测试、没法复用 |

## 七、给嵌入式的你

你有 C 和嵌入式基础，是优势：

- 你懂指针、内存、栈和堆 —— 学 RAII 会特别快
- 你知道手动管理内存多麻烦 —— 所以会真心觉得 RAII 好用

**别被这几句话骗了**：

- "虚函数慢" → 它的开销和你在 C 里用**函数指针表**做多态**一模一样**
- "C++ 会偷偷分配内存" → 只有你写了 `new`、`vector`、`string` 才会有
- "异常有开销" → 嵌入式可以用 `-fno-exceptions`，此时零开销

**RAII 在嵌入式里最实用的地方**：中断临界区、总线占用、看门狗。

```cpp
// 关中断，无论怎么退出都会自动恢复
class IrqGuard {
    public:
        IrqGuard()  { m_Primask = disable_irq(); }
        ~IrqGuard() { enable_irq(m_Primask); }
    private:
        uint32_t m_Primask;
};

void f() {
    IrqGuard guard;
    if (出错了) return;      // 自动恢复中断，不会忘
}
```

**这个思路可以用在**：SPI/I2C 总线、电源域、互斥锁、日志缓冲。

## 八、一页速查

**参数怎么传**

| 情况 | 写法 |
|---|---|
| 小的内置类型（int、bool） | `T v` |
| 大对象，只读 | `const T &v` ← 不确定就用这个 |
| 大对象，要改 | `T &v` |
| 可能没有对象 | `T *v`（要判空） |

**什么时候加 virtual**

| 情况 | 加吗 |
|---|---|
| 基类析构函数 | **必须加** |
| 子类要重新实现的行为 | 加 |
| 只是想在子类复用代码 | **不加**（该用组合） |

**写类的四个问题**

1. 它是什么东西？
2. 它要记住哪些数据？
3. 它自己该会做什么？
4. 它和别人什么关系（是一种 / 有一个）？

**核心口诀**

> **资源让它自动还，数据行为放一起，接口够用就好，能编译期管住就别留到运行时，能用栈就别放堆。**

## 九、学习顺序

| 阶段 | 学什么 | 怎么算学会了 |
|---|---|---|
| 1 | 类、构造函数、析构函数 | 能写出"创建就合法"的类 |

**每学一阶段，配一个动手项目。**

**三条最重要的建议**：

1. **动手 > 看视频**
2. **重写 > 跟敲**
3. **追问原理 > 记住结论**
